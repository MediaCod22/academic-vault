### Подробный разбор

#### 1. Wiki.js ⭐⭐⭐⭐⭐ (РЕКОМЕНДУЮ)

**Стек:** Node.js + PostgreSQL/SQLite/MySQL  
**Docker:** Один контейнер, 5 минут  
**Официальный сайт:** https://js.wiki

**Плюсы:**
- Чистый markdown (как Obsidian)
- Структура папок + теги
- Роли: admin, moderator, editor, guest
- Встроенный Git sync (автоматический push в репозиторий)
- Full-text search
- Красивый Material Design UI
- Поддержка LDAP/Keycloak
- Экспорт в markdown / PDF

**Минусы:**
- Нет bi-directional links (wiki-ссылки `[[статья]]` работают как обычные ссылки)
- Нет graph view (графа связей)
- Нет плагинов как в Obsidian

**Для редактора:** Идеально — структурированная wiki, видит все статьи, может править в браузере.

**Развёртывание:**
```yaml
version: "3"
services:
  wiki:
    image: ghcr.io/requarks/wiki:2
    container_name: wiki
    environment:
      - DB_TYPE=sqlite
      - DB_FILEPATH=/wiki/data.sqlite
    volumes:
      - ./data:/wiki
    ports:
      - "3007:3000"
    restart: unless-stopped
```

#### 2. BookStack ⭐⭐⭐⭐

**Стек:** PHP + MySQL/PostgreSQL  
**Docker:** Docker Compose, 5 минут  
**Официальный сайт:** https://www.bookstackapp.com

**Плюсы:**
- Концепция "Полки → Книги → Главы" (очень удобно для учебников)
- WYSIWYG + Markdown редактор
- Комментарии к страницам
- Роли и права доступа
- История изменений
- Self-hosted, open source

**Минусы:**
- PHP стек (менее модный)
- WYSIWYG по умолчанию (markdown — вторично)
- Нет wiki-ссылок
- Нет graph view

**Для редактора:** Хорошо, если статьи структурированы как "книги". Меньше похоже на Obsidian.

---

#### 3. Outline ⭐⭐⭐

**Стек:** Node.js + PostgreSQL + Redis  
**Docker:** Docker Compose, 20 минут + настройка OIDC  
**Официальный сайт:** https://www.getoutline.com

**Плюсы:**
- Очень красивый UI (Slack-like)
- Markdown + командный редактор
- Комментарии, @mentions
- Интеграция с Google Workspace / Slack / Azure AD
- Collections (папки)

**Минусы:**
- **Требует OIDC провайдер** (Google, Slack, Azure AD, или self-hosted) — без этого не работает
- Нет native markdown файлов (база PostgreSQL)
- Нет Git sync
- Сложный деплой

**Для редактора:** Красиво, но сложно развернуть. Не подходит для быстрого старта.

---

#### 4. Trilium Notes ⭐⭐⭐⭐

**Стек:** Node.js + SQLite  
**Docker:** Один контейнер, 5 минут  
**Официальный сайт:** https://github.com/zadam/trilium

**Плюсы:**
- Иерархия заметок (как в Obsidian)
- Relations map (граф связей!)
- Шифрование
- Attributes (метаданные)
- Self-hosted

**Минусы:**
- **Только 1 пользователь** (не подходит для совместной работы)
- Устаревший UI
- Нет web collaboration

**Для редактора:** Не подходит — один пользователь.

---

#### 5. Docmost ⭐⭐⭐⭐ (новый, 2024)

**Стек:** Node.js + PostgreSQL  
**Docker:** Docker Compose, 10 минут  
**Официальный сайт:** https://docmost.com

**Плюсы:**
- Real-time collaboration (как Google Docs)
- Spaces (папки)
- @mentions внутри документов
- Роли пользователей
- Comment-based feedback
- Modern UI

**Минусы:**
- Новый проект (менее стабильный)
- Нет Git sync
- Нет экспорта в markdown files

**Для редактора:** Отлично для real-time collaboration, но данные lock-in в базе.

---

#### 6. Joplin Server ⭐⭐⭐

**Стек:** Node.js + PostgreSQL  
**Docker:** Docker Compose, 10 минут  
**Официальный сайт:** https://joplinapp.org

**Плюсы:**
- End-to-end encryption
- Web Clipper
- Multi-user (Joplin Server)
- Mobile apps

**Минусы:**
- **Server = только sync**, редактор в десктопе/мобиле
- Нет web-редактора как в Obsidian
- Не подходит для browser-based работы редактора

**Для редактора:** Не подходит — редактору нужен десктопный клиент.

---

#### 7. AFFiNE ⭐⭐

**Стек:** Rust + Node.js  
**Docker:** Сложно  
**Официальный сайт:** https://affine.pro

**Плюсы:**
- Notion + Miro в одном
- Self-hosted (но сложно)
- Modern UI

**Минусы:**
- Сложный деплой
- Не markdown-first
- Overkill для академического письма

## Часть 2: Аналоги Zotero (серверные)

### Критерии сравнения

| Критерий | Описание |
|----------|----------|
| **Web UI** | Полноценный интерфейс через браузер |
| **Citations** | Форматирование цитат (ГОСТ, APA, MLA) |
| **Import** | Импорт из PDF, DOI, arXiv |
| **Export** | Экспорт библиографии |
| **Collaboration** | Совместные коллекции |
| **Self-hosted** | Возможность self-host |

---

### Подробный разбор

#### 1. Zotero Web Library ⭐⭐⭐

**URL:** https://www.zotero.org/user/login/  
**Статус:** Официальный веб-интерфейс Zotero

**Плюсы:**
- Доступ к коллекциям через браузер
- Работает с Zotero sync
- Групповые библиотеки

**Минусы:**
- **Только просмотр и базовое редактирование**
- Нет импорта PDF через web
- Нет полноценного citation formatting
- Основной функционал — в десктопе

**Вывод:** Дополнение к десктопу, но не замена.

---

#### 2. Paperpile / Mendeley ⭐⭐⭐

**Статус:** SaaS, не self-hosted

**Плюсы:**
- Полноценный web UI
- Импорт, цитирование, экспорт
- Коллаборация

**Минусы:**
- **Не self-hosted** (данные в облаке)
- Платные (или freemium)
- Lock-in

**Вывод:** Не подходит для требования self-hosted.

---

#### 3. Zotero API + Custom Web UI ⭐⭐⭐

**Подход:** Использовать Zotero API (read/write) + самописный web UI

**Плюсы:**
- Данные остаются в Zotero
- Web UI под твои нужды
- Self-hosted

**Минусы:**
- **Требует разработки**
- Нет готового решения

**Вывод:** Дорого по времени, не для быстрого старта.

## Итоговые рекомендации

### Для Obsidian: Wiki.js ⭐⭐⭐⭐⭐

**Почему:**
- Ближе всего к Obsidian по духу (markdown, структура, Git sync)
- Простой деплой (5 минут)
- Роли пользователей (редактор может работать)
- Экспорт в markdown → можно перенести обратно в Obsidian

### Для Zotero: Нет полноценного аналога

**Рекомендация:**
1. **Десктопный Zotero** — основная работа с источниками
2. **Zotero Web Library** — быстрый доступ через браузер
3. **Экспорт в markdown** (`scripts/zotero-export.py`) — literature notes в серверную wiki

### Workflow

**Автор (ты):**
1. Пишешь в Obsidian (локально)
2. Zotero для источников (локально)
3. Git push → GitHub + сервер

**Редактор:**
1. Открывает Wiki.js в браузере (http://213.171.9.30:3007)
2. Правит статьи
3. Изменения синхронизируются через Git

**Или через Git напрямую:**
1. `git clone https://github.com/MediaCod22/academic-vault.git`
2. Правит `.md` файлы
3. `git push`
